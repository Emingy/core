# Tooltip: Contextual Hint Component

The `Tooltip` component shows a floating hint near a trigger element on hover. It wraps any content in a transparent `div`, listens for `mouseenter`/`mouseleave`, and delegates rendering to `TooltipProvider` via context.

---

## I. Component Usage

`Tooltip` must be placed inside a `TooltipProvider` (or `AppProvider` if it includes one). It wraps children without affecting layout (`display: contents` on the trigger wrapper).

### Basic Example

<Markdown>
{`
\`\`\`tsx
import { Tooltip } from '@emingy/core/ui';

// Minimal — text + position are required via context
<Tooltip text="Copy to clipboard" position="top">
    <button>Copy</button>
</Tooltip>

// With size
<Tooltip text="Short hint" position="bottom" size="sm">
    <span>Hover me</span>
</Tooltip>

// Left / right
<Tooltip text="Settings" position="right">
    <Icon icon={SettingsIcon} />
</Tooltip>
\`\`\`
`}
</Markdown>

## II. Component Props

<Markdown>
    {`
| Prop Name | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| **\`text\`** | \`string\` | **Required** | Text content displayed inside the tooltip bubble. |
| **\`position\`** | \`'top' | 'bottom' | 'left' | 'right'\` | | Preferred direction to show the tooltip relative to the trigger. Automatically flipped if there is not enough space. |
| **\`size\`** | \`'md' | 'sm'\` | \`'md'\` | Size variant of the tooltip bubble. |
| **\`type\`** | \`'default' | 'error'\` | \`'default'\` | Color variant of the tooltip bubble. \`'error'\` renders a red background. |
| **\`disabled\`** | \`boolean\` | | Prevents the tooltip from showing, in both hover and controlled mode. |
| **\`visible\`** | \`boolean\` | | Switches the tooltip to controlled mode — see section VII below. |
| **\`children\`** | \`ReactNode\` | **Required** | The element that triggers the tooltip on hover. |
`}
</Markdown>

## III. Position Variants

<Markdown>
{`
\`\`\`tsx
import { ETooltipPosition, Tooltip } from '@emingy/core/ui';

<Tooltip text="Above" position={ETooltipPosition.Top}>
    <span>Hover</span>
</Tooltip>

<Tooltip text="Below" position={ETooltipPosition.Bottom}>
    <span>Hover</span>
</Tooltip>

<Tooltip text="To the left" position={ETooltipPosition.Left}>
    <span>Hover</span>
</Tooltip>

<Tooltip text="To the right" position={ETooltipPosition.Right}>
    <span>Hover</span>
</Tooltip>
\`\`\`
`}
</Markdown>

**Flip behavior:** if the tooltip would overflow the viewport in the preferred direction, it is automatically flipped to the opposite side. Flip is calculated after the first render using `offsetWidth`/`offsetHeight` of the tooltip bubble.

**Horizontal shift:** for `top`/`bottom` tooltips, if the bubble is wide enough that centering it on the trigger would push it past the left or right edge of the viewport, it shifts sideways just enough to stay fully visible (with an 8px margin from the edge) instead of overflowing.

## VI. Show / Hide Animation

The tooltip appears and disappears with CSS transitions managed by `TooltipProvider`:

- **Appear**: the bubble slides from a 4px offset toward the trigger and becomes visible via CSS transform transition
- **Disappear**: opacity fades to 0 after `mouseleave`; the bubble is removed from the DOM after the transition completes

<Markdown>
{`
\`\`\`tsx
// Hover sequence:
// 1. mouseenter → showTooltip() → bubble renders at 0 opacity, offset 4px
// 2. requestAnimationFrame → __visible class added → slide + (instant opacity) in
// 3. mouseleave → hideTooltip() → __visible removed → opacity transitions to 0
// 4. transitionend → bubble removed from DOM
\`\`\`
`}
</Markdown>

---

## VII. Controlled Visibility

By default the tooltip is uncontrolled — it shows on `mouseenter` and hides on `mouseleave`. Passing
the `visible` prop switches it to controlled mode: hover no longer has any effect, and visibility is
driven entirely by the prop.

<Markdown>
{`
\`\`\`tsx
// Uncontrolled (default) — shows on hover
<Tooltip text="Copy to clipboard" position="top">
    <button>Copy</button>
</Tooltip>

// Controlled — visible follows external state, hover is ignored
const [visible, setVisible] = useState(false);

<Tooltip text="Copied!" position="top" visible={visible}>
    <button onClick={() => setVisible(true)}>Copy</button>
</Tooltip>
\`\`\`
`}
</Markdown>

**Controlled behavior:**

- Passing any boolean to \`visible\` (including \`false\`) enables controlled mode for that instance.
- The tooltip is shown/hidden via a \`useEffect\` that reacts to \`visible\` changes — not via mouse events.
- \`disabled\` still applies in controlled mode: the tooltip stays hidden even when \`visible\` is \`true\`.
- The tooltip is automatically hidden when the component unmounts while \`visible\` is \`true\`.

---

## VIII. Provider Requirement

`Tooltip` reads `showTooltip` and `hideTooltip` from `TooltipContext`. The component throws an error if rendered without a provider:

<Markdown>
{`
\`\`\`tsx
import { TooltipProvider } from '@emingy/core/ui';

// Required wrapper
<TooltipProvider>
    <App />
</TooltipProvider>

// Or use AppProvider if it wraps TooltipProvider
<AppProvider>
    <App />
</AppProvider>
\`\`\`
`}
</Markdown>

---

## IX. Important Notes

<Markdown>
    {`
- The trigger wrapper uses \`display: contents\` — it is transparent to CSS layout.
- Each \`Tooltip\` instance uses React's \`useId()\` to generate a stable, unique ID for the show/hide cycle.
- If the user moves the mouse away and back quickly, the ongoing exit animation is cancelled and the tooltip reappears without a flash.
- The tooltip bubble is rendered via \`createPortal\` into \`document.body\` to avoid stacking-context clipping.
- \`TooltipProvider\` must be present in the tree; \`useTooltipContext\` throws if it is not found.
- Once \`visible\` is passed (even \`false\`), hover no longer shows or hides the tooltip for that instance.
`}
</Markdown>
